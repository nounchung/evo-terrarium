# R9.1 Validation

Status: implementation, visual QA and automated render-budget gate passed

Issue: [#19 — Living Diorama terrain and light technical spike](https://github.com/nounchung/evo-terrarium/issues/19)

## Implemented scope

- Living Diorama terrain is the default renderer; `?terrain=classic` preserves the R8 renderer for same-seed comparison.
- Contiguous land and water use unified bases with deterministic broad washes, so the simulation grid no longer reads as a field of coloured tiles.
- Marching-contour boundaries add curved shoreline, forest, meadow and deep-water transitions without changing simulation state.
- Meadow/grass detail, forest canopy clusters and water ripples remain deterministic from grid coordinates and biome state.
- Terrain is cached as a texture and rebuilt only when `terrainRevision` changes.
- Canvas data exposes `data-terrain-style`, `data-terrain-revision`, `data-terrain-build-ms` and rolling `data-fps`.
- Unit coverage proves deterministic visual sampling, style selection, water classification and colour mixing.
- Playwright captures Classic/Living evidence on desktop Chromium and the Mobile Safari profile, verifies terrain repaint, records performance samples and fails on application console findings.

## Performance evidence

GitHub Actions software rendering throttles `requestAnimationFrame`: Classic itself measured 4.6 FPS on desktop and 11.3 FPS on the mobile profile. Those values cannot be treated as physical-device FPS. The automated gate therefore always enforces the same-run relative renderer budget and a 100 ms terrain-build ceiling; it additionally enforces the 55/30 FPS targets whenever the Classic control proves that the environment is device-like.

| Renderer | Seed | Profile | Terrain build | FPS samples | Median | Living / Classic |
| --- | --- | --- | ---: | --- | ---: | ---: |
| Classic | `MOSS-1738` | Desktop Chromium | 10.6 ms | 4.6, 4.7, 4.3 | 4.6 | — |
| Living | `MOSS-1738` | Desktop Chromium | 29.5 ms | 4.3, 4.4, 4.1 | 4.3 | 93.5% |
| Classic | `MOSS-1738` | Mobile Safari profile | 12.0 ms | 9.2, 11.6, 11.3 | 11.3 | — |
| Living | `MOSS-1738` | Mobile Safari profile | 40.0 ms | 12.0, 10.8, 11.3 | 11.3 | 100% |

The Living renderer stayed within the allowed 20% relative regression on both profiles and below the 100 ms build ceiling. In the Work Mode cloud browser, the final Living initial build measured 24.7 ms and a water repaint rebuild measured 10.9 ms; its frame ticker was also background-throttled, so its absolute FPS was not accepted as device evidence.

## Gate decision

R9.1 passes its technical-spike Gate. The deterministic PixiJS renderer can support the approved Living Diorama direction without changing simulation behaviour, with a bounded rebuild cost and no material same-environment frame regression. R9.2 may proceed.

The concept illustration remains the visual north star rather than a pixel-identical acceptance target for this spike. Creature redesign, cinematic depth, authored vegetation assets and richer light are explicitly deferred to the later R9 workstreams.
